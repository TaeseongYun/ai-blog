보안 기업 Wiz의 연구진이 GitHub Copilot의 자동 코드 수정(Autofix) 기능을 역이용해 Snowflake의 내부 Jira 시스템까지 침투할 수 있었던 실제 취약점 분석 사례를 공개했습니다. 오픈소스 기여를 가장한 악의적 코드가 AI 자동화 파이프라인을 거치며 어떻게 강력한 공격 벡터로 변하는지를 구체적으로 다룬 글입니다.

이 공격 시나리오가 흥미로운 이유는 AI 보안 도구 자체가 침투의 핵심 경로로 쓰였다는 점입니다. 공격자가 취약점이 포함된 악의적인 Pull Request를 제출하면, GitHub Copilot Autofix는 이를 감지하고 자동으로 수정 코드를 만들어 새로운 PR을 생성합니다. 연구진은 이 과정에서 프롬프트 인젝션과 워크플로 실행 권한의 허점을 파고들어, Copilot이 생성한 PR을 통해 CI 환경의 높은 권한 토큰을 탈취했습니다. 이렇게 얻은 권한은 결과적으로 Snowflake의 내부 Jira 및 인프라 접근으로 이어질 수 있었습니다.

최근 개발 생태계는 Copilot Workspace나 코드 자동 패치 같은 에이전트 기반 자동화 기능을 적극적으로 도입하고 있습니다. 하지만 이번 사례는 AI 자동화가 개입하는 CI/CD 파이프라인에 지나치게 넓은 권한을 부여했을 때 발생하는 위험을 명확히 보여줍니다. AI가 생성한 코드를 맹신하거나 자동 실행되도록 둘 경우, 외부 공격자가 AI를 조종해 손쉽게 보안 경계를 무너뜨릴 수 있습니다. AI 개발 도구를 도입할 때도 최소 권한 원칙과 격리된 샌드박스 환경, 그리고 인간의 검증 단계가 여전히 필수적이라는 점을 되새기게 합니다.
