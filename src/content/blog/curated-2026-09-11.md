전자상거래 플랫폼 쇼피파이(Shopify)가 수년간 이어온 React Native 전략을 철회하고, 모바일 앱 개발을 순수 네이티브 언어인 Swift와 Kotlin으로 전면 복귀한다고 발표했습니다.

이 소식이 개발자들 사이에서 큰 파장을 일으키는 이유는 쇼피파이가 단순한 React Native 사용 기업이 아니었기 때문입니다. 2020년 에어비앤비가 React Native를 포기하고 네이티브로 돌아섰을 때, 쇼피파이는 정반대로 "모바일의 미래는 React Native"라고 공식 선언하며 이 생태계의 가장 강력한 후원자 역할을 자처했습니다. 핵심 앱인 Shopify Mobile을 비롯해 여러 서비스를 전환하고 오픈소스 생태계에도 막대한 투자를 이어왔습니다. 그런 쇼피파이가 5년 만에 방향을 180도 틀어 네이티브 회귀를 공식화한 것입니다.

쇼피파이가 밝힌 회귀 이유는 명확합니다. 규모가 커질수록 프레임워크의 추상화 계층을 유지보수하는 비용이 코드 공유로 얻는 이점보다 커졌기 때문입니다. 각 플랫폼의 최신 API를 제때 도입하기 어렵고, 깊은 디버깅이 필요할 때마다 네이티브와 자바스크립트 양쪽의 맥락을 모두 이해해야 하는 복잡도가 엔지니어링 생산성을 갉아먹었습니다. 결국 최고 수준의 성능과 사용자 경험을 달성하려면 네이티브 코드가 불가피하다는 결론에 다다랐습니다.

요즘 모바일 생태계의 관점에서도 이번 결정은 시사하는 바가 큽니다. 과거 React Native와 Flutter가 네이티브 대비 가졌던 가장 큰 무기는 선언형 UI와 빠른 생산성이었습니다. 하지만 지금은 iOS의 SwiftUI와 안드로이드의 Jetpack Compose가 완전히 성숙해 네이티브 진영 자체의 개발 생산성이 크게 올라왔습니다. 

크로스플랫폼 기술은 여전히 빠른 MVP 검증이나 제한된 리소스를 가진 스타트업에게 강력한 도구입니다. 하지만 제품이 성숙하고 조직 규모가 커질수록 "한 번 작성해 어디서나 배포한다"는 약속 뒤에 숨은 추상화 비용을 언젠가는 정산해야 한다는 점을 쇼피파이의 이번 사례가 다시금 일깨워주고 있습니다.
