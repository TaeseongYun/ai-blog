모바일 웹에 접속했을 때 전용 앱 설치를 집요하게 유도해 놓고, 정작 앱을 실행하면 인앱 브라우저로 원래 웹 페이지를 다시 띄우는 현대 모바일 프로덕트들의 모순된 행태를 비판한 글입니다. 사용자 경험을 개선한다는 명분과 달리, 실제로는 기업의 지표와 데이터 수집을 위해 불필요한 마찰을 만들고 있다는 점을 꼬집습니다.

스마트폰으로 링크를 열었을 때 상단 배너나 전체 화면 팝업으로 "앱에서 보기"를 강요당한 경험은 누구나 있을 것입니다. 하지만 안내를 따라 앱을 설치하고 링크를 다시 누르면, 앱 내부의 웹뷰가 열리며 로그인 세션마저 끊겨 다시 로그인을 요구하는 상황이 빈번하게 발생합니다. 글쓴이는 이를 두고 사용자 편의라는 명분 뒤에 숨은 데이터 추적 권한 확보와 푸시 알림 권한 획득 목적의 다크 패턴이라고 지적합니다.

개발 생태계 관점에서도 이번 논의는 시사하는 바가 큽니다. 모바일 기기의 웹 표준 지원과 PWA 기술이 발전하면서 브라우저만으로도 네이티브 앱에 준하는 기능을 구현할 수 있게 되었습니다. 그럼에도 많은 조직이 비즈니스 지표(설치 수, 체류 시간 등)를 위해 억지스러운 네이티브 앱 전환 경로를 설계하고 있습니다. 이는 개발 리소스를 웹과 앱 양쪽으로 분산시킬 뿐 아니라, 딥링크 깨짐이나 웹뷰 내 인증 세션 불일치 같은 불필요한 기술 부채를 양산합니다. 기술적인 우수성보다 사용자에게 실제로 가치 있는 흐름이 무엇인지 프로덕트 아키텍처 관점에서 다시 돌아보게 만드는 글입니다.
