WebKit 팀이 오랜 기간 해결하기 까다로웠던 Safari의 Top-Level Await(TLA) 교착 상태 및 평가 순서 버그를 해결하기 위해, 기존 JavaScript 기반으로 작성되어 있던 모듈 로더를 C++로 전면 재작성했습니다. 단순한 패치로 풀기 어려웠던 비동기 모듈 의존성 그래프의 구조적 한계를 엔진 레벨의 아키텍처 재설계로 정면 돌파한 사례입니다.

자바스크립트에 Top-Level Await 스펙이 도입된 이후, 모듈 간 순환 참조가 있거나 비동기 평가가 얽히는 복잡한 의존성 트리에서 Safari가 종종 멈추거나 잘못된 순서로 실행되는 문제는 프론트엔드 개발자들에게 오랜 골칫거리였습니다. 당시 WebKit은 모듈 로더 로직의 상당 부분을 JavaScript(내장 빌트인 스크립트)로 구현해 두고 있었습니다. 하지만 복잡한 비동기 실행 그래프를 스펙에 맞게 정교하게 제어하면서도 성능 저하와 스택 오버플로를 피하기에는 고수준 언어 계층에서의 한계가 명확했습니다. 결국 WebKit 엔지니어들은 모듈 평가 상태 머신 전체를 low-level C++ 엔진 코드로 내려 완전히 새로 작성하는 결단을 내렸습니다.

이 사건은 현대 웹 런타임 생태계가 마주한 복잡성을 잘 보여줍니다. 모듈 시스템과 비동기 처리가 결합하면서 브라우저 엔진이 감당해야 할 상태 추적의 난이도는 급격히 올라갔습니다. 번들러 없이 ESM을 직접 로드하는 환경이나 브라우저 기반 동적 로딩이 늘어나는 상황에서, 런타임의 사소한 스펙 해석 차이나 내부 구현 한계는 곧바로 프로덕션 장애로 이어집니다. 이번 재작성은 성능 최적화뿐만 아니라 복잡해진 최신 웹 표준을 견고하게 지원하기 위해 코어 엔진이 어떻게 진화해야 하는지를 명확히 보여주는 엔지니어링 사례입니다.
