오픈소스 LLM 통합 라이브러리로 널리 쓰이는 LiteLLM의 배포본(버전 1.107.0)이 침해되어 백도어와 자격 증명 탈취 코드가 포함된 채 PyPI에 등록되는 사고가 발생했습니다. 보안 분석에 따르면 해당 패키지는 설치 즉시 실행 환경의 민감 정보와 클라우드 인증 정보를 외부로 유출하도록 설계되었습니다.

LiteLLM은 OpenAI, Anthropic, Gemini 등 다양한 모델을 일관된 API 인터페이스로 호출할 수 있어, 최근 많은 팀이 AI 프로덕트나 사내 LLM 게이트웨이를 구축할 때 기본 의존성으로 채택하는 라이브러리입니다. 이번 사고가 특히 치명적인 이유는 공격 타깃의 성격 때문입니다. LiteLLM이 설치되는 환경은 거의 예외 없이 고비용 AI API 키, AWS나 GCP 같은 클라우드 서비스 자격 증명, 데이터베이스 접속 정보 등이 환경변수로 주입되어 있습니다. 공격자는 이 패키지가 설치되는 빌드 환경이나 로컬 개발 머신, 프로덕션 컨테이너의 핵심 자격 증명을 손쉽게 장악할 수 있었습니다.

최근 개발 생태계 관점에서 보면 오픈소스 공급망 공격의 위협이 한 단계 더 정교해졌음을 보여줍니다. 단순한 패키지명 유사 공격(Typosquatting)을 넘어, 이미 널리 쓰이는 오픈소스의 유지보수 파이프라인이나 배포 계정을 직접 탈취해 정상 업데이트로 위장하는 방식이 일상화되고 있습니다. 특히 생성형 AI 열풍으로 빠르게 등장한 수많은 신생 라이브러리들은 채택 속도에 비해 보안 검증 체계나 릴리스 파이프라인의 성숙도가 상대적으로 낮아 공격자들의 매력적인 타깃이 되고 있습니다.

자동화된 의존성 업데이트 도구(Dependabot, Renovate 등)를 맹신하기보다 패키지 버전을 엄격히 고정(Pinning)하고, 빌드 파이프라인의 아웃바운드 트래픽을 제한하며, 환경변수 접근 권한을 최소화하는 방어 조치가 이제 선택이 아닌 필수가 되었습니다. LiteLLM을 프로젝트에 사용 중이라면 즉시 설치된 버전을 확인하고, 침해 버전 사용 여부 점검과 함께 관련 API 키 전면 재발급을 고려해야 합니다.
