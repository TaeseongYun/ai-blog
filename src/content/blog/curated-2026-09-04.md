Claude, Codex, Cursor 같은 코딩 에이전트에게 자율적으로 작업할 수 있는 환경을 열어주었을 때, 모델들이 실제로 어떤 CLI 도구를 선택하고 설치하는지 17,000회의 실행 데이터를 통해 측정한 흥미로운 분석 글이 공개되었습니다.

단순히 코드 자동완성을 넘어 복잡한 레포지토리를 직접 탐색하고 디버깅하는 에이전트 워크플로가 일상이 되면서, 에이전트가 주어진 샌드박스 안에서 '어떻게 문제를 해결하는가'는 중요한 관심사가 되었습니다. 분석에 따르면 에이전트들은 인간 개발자가 흔히 사용하는 검색 도구(ripgrep, fd 등)나 빌드 도구를 스스로 설치해 활용하는 경향을 보였으며, 모델의 종류와 프롬프트 지침에 따라 도구 선택의 편차가 뚜렷하게 갈렸습니다. 특히 정교한 최신 도구를 찾아서 설치하려다 패키지 관리자 오류에 빠지는 모델이 있는가 하면, 시스템에 기본 내장된 원시적인 셸 명령어(find, grep)만으로 우직하게 작업을 완수하는 모델도 있었습니다.

이 결과는 요즘 개발 생태계에 몇 가지 시사점을 던집니다. 첫째로 에이전트용 런타임 환경의 표준화 문제입니다. 에이전트가 매번 도구를 설치하느라 토큰과 시간을 낭비하지 않도록, 에이전트 친화적인 사전 구성(pre-warmed) 컨테이너를 준비하는 것이 비용 최적화의 핵심으로 떠오르고 있습니다. 둘째는 CLI 도구의 설계 패러다임 변화입니다. 지금까지의 개발 도구는 인간의 눈에 보기 좋은 컬러 출력과 인터랙티브 UI에 집중했지만, 앞으로는 LLM이 파싱하기 쉬운 JSON 스트림이나 간결한 에러 메시지를 반환하는 '에이전트 친화적 인터페이스'를 갖춘 도구들이 경쟁력을 얻게 될 것입니다.

에이전트에게 더 많은 권한을 위임하는 실무 환경을 고민하고 있다면, 모델의 지능뿐 아니라 모델이 손에 쥐게 될 '도구 상자'를 어떻게 설계해야 할지 좋은 힌트를 주는 글입니다.
